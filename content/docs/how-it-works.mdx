The mechanism in full, including what we can do with your signature and what we cannot.

## The sequence

```
payer                merchant                facilitator            Whitechain
  │                     │                         │                     │
  │── GET /report ─────▶│                         │                     │
  │◀── 402 + terms ─────│                         │                     │
  │                     │                         │                     │
  │ sign TransferWith-  │                         │                     │
  │ Authorization       │                         │                     │
  │ (offline, no gas)   │                         │                     │
  │                     │                         │                     │
  │── GET /report ─────▶│                         │                     │
  │   PAYMENT-SIGNATURE │── POST /verify ────────▶│                     │
  │                     │                         │── eth_call ────────▶│
  │                     │◀── isValid: true ───────│                     │
  │                     │                         │                     │
  │                     │  (your handler runs)    │                     │
  │                     │                         │                     │
  │                     │── POST /settle ────────▶│                     │
  │                     │                         │── transferWith-     │
  │                     │                         │   Authorization ───▶│
  │                     │                         │   (we pay the WBT)  │
  │                     │◀── tx hash ─────────────│◀── receipt ─────────│
  │◀── 200 + content ───│                         │                     │
  │   PAYMENT-RESPONSE  │                         │                     │
```

Note the ordering: your handler runs between verify and settle. A request that fails inside your code does not charge the customer.

## What the payer signs

EIP-712 typed data against the token's own domain:

```solidity
TransferWithAuthorization(
  address from,
  address to,
  uint256 value,
  uint256 validAfter,
  uint256 validBefore,
  bytes32 nonce
)
```

Every allowlisted token reports the canonical typehash — `0x7c7c6cdb…1a2267` — so this is standard EIP-3009, not a variant.

The signature is a message, not a transaction. It is never broadcast by the payer, costs nothing to produce, and requires no gas token in the signing account.

## What we do on `/verify`

Read-only. No transaction, no gas:

1. Recover the signer from the signature and confirm it equals `authorization.from`. Handles EOAs and EIP-1271 smart accounts.
2. Confirm the payer's token balance covers `value`.
3. Confirm `validAfter`/`validBefore` make the authorization live now, and that it satisfies the merchant's `maxTimeoutSeconds`.
4. Confirm the asset and network match what the merchant asked for and what we allowlist.
5. Simulate `transferWithAuthorization` to confirm it would actually succeed.

This is all handled by `@x402/evm` — the official implementation, not a reimplementation of signature recovery. It is cheap enough to call freely.

## What we do on `/settle`

1. Re-run the checks above, including the simulation, because state can have changed since verify.
2. Submit `transferWithAuthorization(...)` from our signer, paying the WBT fee.
3. Wait for the receipt and return the hash.

The on-chain transaction has `from` = our signer and emits a `Transfer` from the payer to the merchant. Those are two different addresses on purpose: we pay the fee, we never touch the funds.

### Every settlement is tagged

Each transaction we broadcast carries a note, modelled on the transaction note the Algorand x402 facilitator writes:

```
x402-payment-v1-1793918603937
```

That is `x402-payment-v1-` plus the broadcast time in milliseconds. EVM transactions have no note field, so it is appended to the end of the `transferWithAuthorization` call data. The token contract ignores bytes after its arguments, so the transfer is exactly the same; the note just stays in the transaction's input data for good. That is how you can tell, from the chain alone, that a payment went through this facilitator. The [transaction log](/logs) shows it under each hash.

Read it back from any settlement:

<NetCode lang="bash">
{`cast tx 0xYourTxHash input --rpc-url {{rpc}} \\
  | tail -c 59 | cast --to-ascii        # → x402-payment-v1-1793918603937`}
</NetCode>

It costs about 500 extra gas per settlement, which we pay.

If the broadcast lands but the receipt wait times out, we return `settlement_pending` **with the transaction hash**. That is not a failure — the payment may well confirm. A retry for the same payload reconciles against the already-broadcast transaction rather than sending a second one.

## The trust model

What we are able to do with a signature you hand us:

| | Possible? | Enforced by |
| --- | --- | --- |
| Change the amount | No | `value` is in the signed message |
| Redirect the funds | No | `to` is in the signed message |
| Pay ourselves | No | Same — `to` is fixed |
| Replay it | No | Single-use `nonce`, consumed on-chain |
| Use it after it expires | No | `validBefore`, checked on-chain |
| Take custody of the tokens | No | They never enter our address |
| **Decline to submit it** | **Yes** | Nothing prevents this |
| **Learn that the payment exists** | **Yes** | We see payer, merchant, amount, resource |

That last row is the real cost of using a facilitator: metadata. We see who paid whom, how much, and for which URL — and we publish it in the [transaction log](/logs). We do not store signatures or authorization nonces, because those are the only parts that would be dangerous to keep.

Our blast radius if we were fully compromised is the WBT in our gas wallet. There is no pool of customer funds to lose, because there is no pool.

## Why no Permit2

The x402 `exact` scheme has a Permit2 path for tokens that lack EIP-3009. It needs an extra approval the payer must first grant to the Permit2 contract — which costs gas, which defeats the point unless that approval is itself sponsored.

Every asset we allowlist supports EIP-3009 natively, so we use the direct path and skip the problem. Permit2 and `x402ExactPermit2Proxy` are in fact deployed on Whitechain Sepolia if you want to build on them yourself; on mainnet, Permit2 is deployed but the x402 proxy is not. See [network reference](/docs/network-reference).

## Where the gas actually goes

A settlement costs roughly 70,000–90,000 gas. Whitechain's minimum base fee is 5 gwei, so one payment costs on the order of 0.0005 WBT. We cap each settlement at 300,000 gas — see [limits](/docs/limits).

Every figure we spend is in the [log](/logs), per payment.
