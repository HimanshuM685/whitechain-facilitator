Whitechain Sepolia is chain `1874`. Tokens on it have no value. This is where you build.

## What you need, and what you do not

| | Needed? | Why |
| --- | --- | --- |
| Test USDT | **Yes, for the payer** | It is what gets transferred. |
| Test WBT for the payer | **No** | That is the entire point. Leave it at zero. |
| Test WBT for you, the developer | Only to deploy contracts | Paying for an API needs none. |

## 2. Get test WBT (for deploying, not for paying)

The [faucet]({{faucet}}) hands out test WBT. You need it to deploy a contract or send an ordinary transaction. You do **not** need it to pay for an x402 endpoint — if you find yourself topping up the payer's WBT to make a payment work, something is wrong with the setup, not the balance.

## 3. Get test USDT

USDT is the only token served. Sepolia USDT supports EIP-3009 natively:

- **USDT** — <NetVal k="usdt" />

Bridge test tokens with the [testnet bridge]({{bridge}}), or ask in the Whitechain developer channels. Check what landed:

<NetCode lang="bash">
{`cast call {{usdt}} "balanceOf(address)(uint256)" $AGENT --rpc-url {{rpc}}
cast call {{usdt}} "decimals()(uint8)" --rpc-url {{rpc}}   # 6`}
</NetCode>

## 4. Confirm the token really is EIP-3009

Worth doing once for any token you plan to accept, because a token without it cannot be paid gaslessly at all:

<NetCode lang="bash">
{`# Must return the canonical typehash:
# 0x7c7c6cdb67a18743f49ec6fa9b35f50d52ed05cbed4cc592e13b44501c1a2267
cast call {{usdt}} "TRANSFER_WITH_AUTHORIZATION_TYPEHASH()(bytes32)" --rpc-url {{rpc}}`}
</NetCode>

If that call reverts, the token has no EIP-3009 support. (This is exactly how mainnet USDT was ruled out — see [supported assets](/docs/supported-assets).)

## 5. Run the whole loop

Price a route, then pay it:

<NetCode lang="bash">
{`# Terminal 1 — your merchant server from the merchant quickstart
npm run dev

# Terminal 2 — unpaid request shows the terms
curl -i http://localhost:3000/api/report

# Terminal 3 — an agent with 0 WBT pays it
npx tsx agent.ts`}
</NetCode>

Then prove it to yourself on the explorer. Open the settlement hash and check two things:

1. The USDT `Transfer` event goes **payer → merchant**. Not through us.
2. The transaction's `from` is **our facilitator signer**, and the fee came out of our balance.

That single screen is the whole idea.

## 6. Check our testnet status

<NetCode lang="bash">
{`curl -s {{facilitatorUrl}}/health | jq '.networks[] | select(.network=="testnet")'`}
</NetCode>

You get our signer's WBT balance and an estimate of how many settlements are left — see [limits](/docs/limits).
